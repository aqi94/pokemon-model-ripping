# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A pipeline that converts ripped Pokémon game models into one common format (rigged glTF with every animation as a named clip, plus a `manifest.json`), the Blender-community formats derived from it (FBX for Unreal, OBJ+MTL, PNG textures, laid out like the `Adaman/` sample from models.spriters-resource.com), and a modelviewer.lol-style web viewer that reads the common format. Every game gets its own importer under `pipeline/importers/`; nothing downstream of an importer may know which game an asset came from.

Current scope: Pokémon Legends: Z-A (`ZA-*` zips). Since added (see sections below): SV, GO, BDSP, LA, SwSh, LGPE, HOME, UNITE, Stadium 2.

## Principles (user decisions; details in `.claude/skills/engine-rules`)

1. **No per-model fixes.** A model that looks off is an edge case of the game engine we have not covered yet. Fix it with a rule over data fields and survey every model the rule selects. Do not use id/species tables or per-model override files. User scene choices (ball, pose, camera, lighting) are saved looks (`out/<game>/<id>/configs.json`), not code. Assume that every error we spot affects several more models, within the same game, that we did not notice.
2. **Every number has a purpose until shown otherwise.** Unread or unexplained values go in `docs/ledger/<game>.json` (`python -m pipeline audit-fields --game <g>`). Constants we had to fit are tagged `# FITTED: <what> on <models>, <date>`.
3. **Animations come from rig families.** Generic characters share an abstract base rig and its clip sets. Pick donors from data first, then by rig signature (`python -m pipeline --game <g> rigs families`). See `.claude/skills/animation-inheritance`.
4. Unless explicitly told otherwise, fan out agents at models Sonnet or lower. Assign the sub-agent the lowest model that is appropriate, and rely on orchestrating agent instructions to ensure goal alignment.

"Tint to surface colour" (`tinted`) draws the line as the mesh's own albedo x 0.3 (`TINT_DARKNESS`) instead of one flat colour.

Viewer lighting (`viewer/src/scene/environment.ts`) uses the standard game-engine model rather than ad-hoc knobs: light colour as Kelvin (key / back / sky) or explicit `keyColor/skyColor/backColor` (game-data presets; a Kelvin slider clears them), key + back (rim) directional lights + sky/ground hemisphere ambient, exposure + tone mapping (linear / ACES / AgX / Khronos neutral / `hable` = Hable's filmic curve with the game's own `Pfx*` parameters, `viewer/src/scene/hable.ts`, baked into three's CustomToneMapping chunk + `customProgramCacheKey`) + contrast/saturation grade, bundled as named `LIGHTING_PRESETS` (Options > Lighting). Presets carry an optional `game` tag as provenance only (`bdspVs` bdsp, generated `ZA_PRESETS` za and `SV_PRESETS` sv); the dropdown lists every preset for every game (user decision: lighting options are constant across games). `studio` = the old defaults (VS screenshots, unchanged). In the Game shader the first directional light is the key (toon band, shadow colour on its far side, drives the ambient tint); later lights are back/rim lights that only add light on their lit side. The material rim terms add a view-dependent glow independent of the lights, so `rim` is per scene: it was what made Emma's dark hair look grey indoors (fit drove it to 0). Rim and back rim are multiplied by the albedo, and `SpecularOffset` widens the lobe by lowering the exponent (`n * (1 - 0.75*offset)`). Adding the offset to N·H before the power clipped a ~35° cap to full intensity: the Poké Ball (`ob0204`, layer specular 1.0, offset 0.3-0.5, rim 0.6 + back rim 0.6) rendered pink-white instead of the game's saturated red with a small highlight. The old hand-fitted `night`/`indoorWindow` presets are now `za_battle_zone_night`/`za_indoor_hotel` (same screenshots under refs/za/, refitted).
Calibrate a preset against a screenshot with `node tools/match_lighting.mjs samples/<x>_regions.json --preset <id> [--fit] [--out png]` (dev server running): the regions file holds model/clip/frame/camera and matching boxes on the screenshot and the render, and the script prints per-region CIE76 dE and the best env. `indoorWindow` was fitted to `samples/detective_handclap01_*` (mean dE 4.9 vs 13.4 for studio); coordinate descent gets stuck easily, so try several `--env` starting points.

**Gameplay-frame calibration (Z-A scene presets, `tools/lightrefs/README.md`):** `refs/<game>/<scene>/` holds YouTube frames (git-ignored PNG) + tracked JSON sidecars/regions/fit.json/notes.md, one folder per scene from `tools/lightrefs/scenes.py` (13 Z-A scenes: lumiose day sunny/overcast/rain/dusk/night street, battle zone night, wild zone day/night, hotel, cafe, lab, indoor night lamp, sewers; fit profiles in `fit_profiles.json`, seeds in `seed_envs.json`). `python -m tools.lightrefs.fetch_frames doctor|search|info|scout|around|grab|regrab` (yt-dlp + imageio-ffmpeg; only DASH `https` formats, HLS cannot be seeked; frames are seeked directly in the 2160p stream and downscaled to 1920 wide; scouting = parallel per-tile seeks into labelled contact sheets, ~25 s per 10 min of video; known Switch 2 4K60 uploads: Shirrako `4spEtYJBlVE`/`6qiJ2FnPSFM`, BeardBear `eDzTIHRGsEw`). `node tools/fit_scene.mjs --scene refs/za/<scene> --seeds a,b --profile p --fit --write .../fit.json --debug-out ... [--probe]` fits one env jointly over every shot (multi-seed + direction restart, `--probe` = material-id pass with per-material centroids and `modelBox`, `--debug-out` = boxes drawn on both images; survives dev-server hot reloads). `python -m tools.lightrefs.build_presets --game za` -> generated `viewer/src/scene/zaPresets.ts` (`ZA_PRESETS`, ids `za_<scene>`), `refs/za/index.json` for the viewer's Reference tab (`ReferencePanel.tsx`: Off / Overlay / Side by side, applies clip/frame/`ViewerScene.setCameraPose` + the scene preset; `/refs/` is served from `../refs` by `vite.config.ts serveDir`) and `out/za_lighting_sheet.png`. One Haiku agent per scene, editing only its folder; the dev server must not be hot-reloaded while fits run (the fitter re-initialises but loses time). `--align` (subjectBox + yaw + optional subjectCut in the regions JSON) places the camera; `--auto-regions` writes flat single-material boxes; agents only verify the debug PNG. Known viewer gap found this way: trainer clips `yes01`, `no01`, `speak01_loop` are upper-body layer clips whose root (`waist`) scale is 0, so the model vanishes when they play alone (the game masks them with `.tracl`); use `speak02_loop`/`glad01`/`defaultwait01_loop` for dialogue poses.

Conventions the IR enforces: Y-up metres; quaternions (x,y,z,w); `Joint.inverse_bind` is a column-vector 4x4 (the Trinity file stores row-vector 4x3, so the importer transposes); `Skeleton.palette[i]` is the joint index that vertex joint index `i` refers to (Trinity rig/JointInfo index, not node index); textures are (H,W,4) uint8 top row first; UVs are glTF convention (top-left origin). Trinity UVs are bottom-left origin, so the ZA importer flips V and negates tangent handedness; verified visually on Pikachu (as-is puts the back stripes on the arms).

## Z-A format facts (verified on real files, not just docs)

- All `.tr*` files are FlatBuffers without identifiers; `.trmbf` too. Field indexes match the Scarlet/Violet layouts used by gftool/ChicoEevee's importer. `fb.dump()` prints a heuristic tree for new file types.
- `.trmdl` -> mesh files (LOD0 first, `_lodN.trmsh`), skeleton, material files. `.trmsh` -> shapes with vertex declarations (usage enum: 1 pos, 2 nrm, 3 tangent, 6 uv, 7 joints, 8 weights; formats 51 f32x3, 43 f16x4, 48 f32x2, 22 u8x4, 39 u16x4) and parts (index range + material). `.trmbf[i]` -> index/vertex byte vectors for shape i.
- `.trskl` nodes carry SRT (euler XYZ radians) + parent + `joint_info` (rig index); `joints[rig]` has the inverse bind 4x3. Pokémon have ~110 nodes / ~90 rig joints; trainers ~190.
- `.trmtr` material: shader `IkCharacter`; texture slots `BaseColorMap/NormalMap/OcclusionMap/LayerMaskMap/...`; colours `BaseColorLayer1..4` are blended over the (near-white) albedo using the `_lym` mask channels R,G,B,A = layers 1..4 (`importer.bake_layers`). `_rare.trmtr` = shiny: same textures, different layer colours. `.trmmt` lists variant sets ("normal", "rare").
- `.tranm`: info (loop, frame count, fps=60) + per-bone tracks; each channel is a union: 1 fixed, 2 one key per frame, 3 keyed u16 frames, 4 keyed u8 frames. Rotations are 48-bit packed quaternions (3x15-bit in [-pi/4, pi/4], 2-bit index of the omitted component, sign bit). Keyed tracks may repeat frames; importer dedupes and decimates.
- Textures: BC7 (albedo, lym), BC5 (normals), BC4 (ao/masks), all block-linear. Mip 0 only.
- Animation naming `<model>_<5-digit index>_<name>.tranm`; the index is stable across species (00000 defaultwait, 00010 defaultidle, 00030 walk, 00100 run...). Pokémon: median 59 clips. Indexes 10000/20000/30000+ are whole alternate sets reusing the same names (Pikachu, Charizard); the importer suffixes them ` [setN]` and sets `Clip.group`.
- Layer masks can be larger than the albedo (Charizard: 1024 vs 512). Resize them per channel (`importer.resize_rgba`): Pillow's RGBA resize premultiplies alpha and zeroes the colour channels where alpha is 0, which silently produced white Pokémon.
- UV rules (all verified against the models.spriters-resource.com preview of Bulbasaur): V origin is bottom-left (flip for glTF); each material's parts sit in their own integer V tile (body_a 0..1, body_b 1..2, cheeks 2..3: drop the tile); the material's `UVScaleOffset` (su, sv, ou, ov) is applied first, typically (2,1,0,0) with a `mirror` U sampler meaning the texture stores half of a symmetric layout. The importer bakes mirrored textures to full width (mirror-concatenated) so every consumer gets plain repeat UVs, but ONLY when that axis has scale >= 2 (a mirror sampler with scale 1 never leaves [0,1]: Pikachu ears/tail, Charizard eyes); the normal map keeps its own scale via `KHR_texture_transform`. Sampler fields are `.trmtr` material field 3, entries parallel to the texture list, wrap enum 0 repeat / 1 clamp / 6 mirror / 7 mirror-once (treated as clamp: identity inside [0,1]; eyes use it). A V scale of 2 on a clamped axis (Pikachu cheeks) is simply scale-then-tile-drop.
- Layers are applied in order, each covering the previous (lerp by its mask channel), not averaged: Pikachu's cheek mask has layers 1 and 2 both fully on and the cheek is layer 2 (red); averaging gave orange.
- Layer colours (`BaseColorLayerN`) are linear-light floats; the albedo is sRGB. Bake in linear space (`srgb_to_linear` / `linear_to_srgb`) or everything comes out dark and dull (lime bulb became dark green).
- Eye glints are emission layer 5 masked by `HighlightMaskMap` (`EnableHighlight`, `EmissionIntensityLayer5`); baked as an emissive texture.
- **Colour layer 5** (`NumMaterialLayer 6`, `importer._layer5`): a fifth layer over layers 1-4 whose mask is `OpacityMap1` (R), sampled on UV set `UVIndexLayer5` through `UVScaleOffset5`; colour `BaseColorLayer5`, shadow `ShadowingColorLayer5`, glow `EmissionColorLayer5 x EmissionIntensityLayer5`. Unlike the main `UVScaleOffset` it samples `uv * scale - offset` (Trinity space): with +offset the clip tracks of Crabrawler/Crabominable (U -> -0.75), Xerneas (U 0.5 -> 0) and SV Black/White Kyurem (rest V -0.6/-1.0) never or always show the layer. Static UV0 layers with the albedo's scale are baked (`bake_extra_layer`, lit + shadow + emission): Yveltal (Z-A internal `pm0769`) gets its black wings/back/veins from it (it rendered grey/red before). UV1 or clip-moved layers become overlay materials `<mat>~l5` on a copy of the triangles (`_layer5_overlay`, `layer_overlay_uvs`, `extras.layer_overlay`, `uv_track_gain` (-1, 1) for the viewer's clip offsets): Xerneas (`pm0768`) horn tips get a glow its battle clips (`roar01`, `rangeattack*`) sweep along UV1; off at rest. 22 Z-A materials (14 models) + 14 SV materials (11 models) use it. Z-A Pokémon above ~#720 use internal ids (pm0768 Xerneas, pm0769 Yveltal); `sv/pm0716/0717` are not Xerneas/Yveltal despite their labels. Xerneas' Active Mode (cream horns: `samples/za_xerneas.png` battle shot, `samples/xerneas_active_swsh.png`) is NOT this layer but `importer.MODE_SWITCH`: field clips show `horn_a` (Neutral), battle clips (`battlewait`, `stepin`, `roar`, `attack*`...) show `horninc_a/b` (rainbow tips, crown leaves) + `backinc`, while the shared horn bodies (`body_b_00` layer 4 on `body_a_mesh`) carry their cream as `EmissionColorLayer4` at intensity 0 (layer 3 = pastel leaves). `~active` material copies switch those chromatic intensity-0 layers on (1.0; white = authoring default, skipped), active-only meshes use them, and the shared triangles split into `body_a_mesh_neutral/_active` whose per-clip visibility copies `horn_a` / `horninc_a`. So the viewer shows Neutral in field clips and Active in battle clips, shiny included.
- Falinks (ZA/SwSh internal `pm0923`, Mega `_51`): its "black" is authored as body layer 4 = linear 0.10 (sRGB 89,84,80), and the in-game Pokédex shot (`samples/za_mega_falinks.png`) measures ~sRGB 84-97: keep it, it is not pure black (Umbreon's black is 0.005; SwSh's albedo uses 45,42,38). The eye expressions live in the `LowerEyelidColorMap` (`EyelidType Lower`): its alpha is the visor with holes in the eye shapes, a 4x4 atlas of right/left pairs (open, half, closed, "> <", spirals, the Mega leader's side dots) at UV scale 1, driven by `UVScaleOffset4`. Through the holes the layer mask paints the eye (R = layer 1 blue everywhere, so a thin ring shows around the G white; B/A = the leader's dots), sampled with `UVScaleOffset` (2, 1) about `UVCenter0` (0.5, 0.5) through a mirror sampler (both eyes read the mask's left column). The game offsets BEFORE scaling: `uv' = (uv + o - centre) * scale + centre` (offsetting after the scale misplaced the white in the offset-0.5 expressions, Mega leader in `megaappeal01`). Clips move both offsets in lockstep, so `eye_fix` bakes the eye once in lid space and switches the material to plain (1, 1) UVs driven by `UVScaleOffset4` (`extras.uv_track_param`). Visor = `BaseColorLayer8` (= body layer 4), its shadow tint `BaseColorLayer10`. Drawing the shapes from the mask's G channel (earlier attempts) missed every expression and put the leader's dots between the eyes. The bake is generic (`EyelidType Lower` + a non-trivial lid + `UVScaleOffset4` scale 1; lid colour = lid RGB x layer 8, SV lids carry their own colour) but gated by `_lid_atlas_unfit`: only materials whose clips move eye and lid offsets in lockstep get it (ZA Falinks x2, Carbink... `pm0703`, Frogadier `pm0724` `eye_b`, Yamask front eyes; SV Falinks `pm0923`, `pm1044`, `pm1045`). Froakie (`pm0723`, lid parked at V 2.0 off the clamp-sampled atlas), Ash-Greninja (`pm0725_11`), Munkidori and Terapagos (lid slides over a still eye) need the lid as a separate viewer layer and keep the old path. A one-colour eye under the lid skips the lockstep gate (any offset looks the same: Greninja `pm0725_11_00` field `eye_b` = black eye under a white lid with dash holes), unless a clip parks the lid off the atlas (`_lid_off_atlas`, Froakie). **Sliding lids** (`EyelidType All/Upper`, and Lower lids that fail the gate) become overlay materials `<eye>~lidU` (UpperEyelidColorMap x layer 7, shadow 9, `UVScaleOffset3`) / `<eye>~lidL` (LowerEyelidColorMap x layer 8, shadow 10, `UVScaleOffset4`) on a copy of the eye triangles (`_lid_overlay`, `lid_overlay_uvs`; clamp sampler, `extras.uv_track_src/param` so clips drive them; viewer: polygon offset, no depth write). Verified on Greninja `eye_a`: lid scale (0, 1) = a straight edge from the lid texture's centre column; larger V offset = more open (rest -0.5 shut, battle 0.206 half-lidded glare, blink to -0.253, sleep -0.253, `down` raises the lower lid to 0.126). The old static "Malamar" lid paint only runs without an upper overlay, and never from a flat `EyelidShadowMaskMap`. Upper lid = `UVScaleOffset3`, not 2: across ZA/SV/LA 2 never moves alone (equal to 3 in every clip keying both), while 3 alone drives SV Sinistcha (`pm1134_11/12`: its `UpperEyelidColorMap` is a 2x4 expression atlas, an opaque lid with eye-shaped holes; V 0 spirals -> 0.5 closed = blink) and ZA `pm0860_51`. Only Z-A writes `EnableEyeOptions`; the overlay used to require it, so every SV (131 materials) and LA (23) sliding lid was missing and Sinistcha's eyes were painted solid green by the Malamar path. The overlay's V tile comes from the eye part's own vertices (`part_tile`): SV shapes share one vertex buffer between body (tile 1) and eyes (tile 0), and the whole-buffer median put Corphish's lids one tile off, covering the eyes (also `layer_overlay_uvs`: Cutiefly `pm0834`'s pale face patch, layer 5 on UV1 tile 1, never showed). Viewer draw order: layer-5 overlays `renderOrder -1` (before the blended eyes, or the face patch covered an eye), lid overlays `1` (after their eye). The "dark eye mesh -> swap to brighter sibling" rule now needs the eye dark everywhere (99th percentile < 60): Morpeko's normal eye (Z-A `pm0941_11_00`, black + white highlight, mean 44.6) was swapped for the red Hangry eye. Frogadier's field clips (defaultwait, walk, idle...) show `eye_b` = the relaxed dash expression (user-confirmed: concept art), its battle clips show `eye_a` (open eye + eyelid mesh, matches HOME); the viewer's default clip is a field clip. The importer also applies `UVCenter0` generally (it only matters when the scale != 1: Falinks, Budew `pm0406` eyes).
- **Segment scale compensate:** Trinity joints are Maya-style: a parent's scale moves its children (their offsets scale) but is not inherited. Clips retract tongues/vines/feelers with stretch-axis-only scale tracks along whole chains (Seviper `tongue_01..04` (0.15, 1, 1), Florges ZA/SV `pm0715_*` feelers (0.05, 1, 1); ~850 ZA/SV/LA models). glTF inherits scale, so `importer.split_scale_joints` gives every bone with a non-uniform scale (any clip, or rest) and children a leaf joint `<bone>_scale` (identity local, same inverse bind) that takes its skin weights and scale track; the bone stays unscaled and its children's translation tracks become `parent_scale * t`. Exact, unlike compensating child scales (shears under a rotated child: Binacle's bent arm) or dropping the tracks (the old rule: tongues/vines stuck out). Clips that scale such a bone uniformly (hide at 0) keep the scale on the bone, so the chain still hides. Children whose `segment_scale_compensate` is off (`Joint.scale_compensate`, SV `*_eyeball_segoff`) inherit instead: they hang under the leaf with raw offsets.
- **Material tracks in `.tracm`** (`trinity.parse_tracm_materials`): shape[4] -> [2] materials {0 name, 2 params {0 name, 1 channel table: one slot per component, slot[0] = vector of keys {0 frame f32, 1 value f32}}}. Keys are held (step), not interpolated. `UVScaleOffset` offset changes become `Clip.uv_offset` with `uv_offset_mode = "gltf_step"` (glTF UV space, +y down the image, halved on mirror-doubled axes; manifest `uvOffsetMode`; viewer `applyUvOffsets` snaps instead of lerping and also drives `name@rare`). Verified: Falinks' blink steps V 0 -> 0.25 -> 0.5 down the rows open/half/closed. Not imported yet: tracks that change the scale (Budew), `UVScaleOffset1..5`/`Normal`/`LayerMask` (iris layers etc., need unbaked layers), colour/emission params. Survey: 498/590 ZA, 808/976 SV, 284/353 LA Pokémon and the ZA `motion_uq` trainers carry such tracks (almost all eyes); GLBs converted before this lack them.
- Layer enable: a layer with alpha > 0 is on; with alpha 0 it is on unless its colour is one of the tool's placeholder swatches (red 1,0,0 / blue .014,.177,.981 / green .102,1,0 / cyan .023,.972,.875), see `importer._layer_strength`. Tarragon's eyelashes (layer 1, near-black) and brows (layer 2) have alpha 0 but are real. Mask alpha channels are often fully on, so placeholders must be filtered.
- (Superseded detail) `BaseColorLayerN` alpha is the layer's enable/strength: 1.0 on Pokémon, 0.0 on trainer clothing/skin (which ship a black placeholder `sh_black_msk` whose decoded alpha is 1). The bake multiplies each mask channel by that alpha, otherwise skin turns teal. Skin tone comes from the material's `BaseColor` factor times the albedo.
- Shadow colour = layer colour x `ShadowingColorLayerN`, undiluted (verified: Griselle's bow albedo x layer 4 = the in-game near-black navy). `ShadowStrength` is the shader's blend toward it, and `ShadowingGIGain` tints ambient light toward it everywhere (viewer "Ambient tint" slider). Screenshots carry scene light (daylight sky turns grey cloth blue), so match them with the Environment sliders, not the bake. When no layer is baked the glTF factor keeps `BaseColor` and the shadow texture is tinted by it too (`shadow_bc`, in its key hash): the Game shader uses the shadow texture *instead of* factor x map, so an untinted one showed the raw near-white albedo on the shadow/ambient side (SV Rika's teal hair went grey-sage, SV eyelashes and ZA bare skin went pale).
- Trainer clothing colours: base layers are white/disabled and the albedo is the lit colour, but `ShadowingColorLayerN` still carry the garment hues (Griselle: blue-grey jacket, black bow); the shadow bake follows the mask wherever a shadow layer exists even when base layers are disabled.
- Trainer faces: `ColorTableMap` is `ColorTableDivideNumber` zones wide (1, 2 or 4); top half = each zone's lit tint, bottom half = its shadow tint. The face `_lym` channels R,G,B,A are layers 1..4 and `BaseColorIndexN` (1-based) picks layer N's zone (`importer.apply_color_table`); every face has index1 = 1 = skin (R covers ~87%), A = mouth. Picking the zone from R's value (old rule) always chose the last zone: Mable (tr0023, 4 zones) got a black face, 2-zone faces got no skin tint (Tarragon pale instead of tan, Grisham/Griselle paler than their hands). Lit = albedo x top cell (base colour), shadow = albedo x bottom cell (shadow texture).
- Layer colours replace the material `BaseColor` tint instead of stacking on it: `bake_layers(base=BaseColor)` starts unmasked texels at albedo x BaseColor and lerps each layer to albedo x its colour; BaseColor is baked and the glTF factor set to 1. Grisham's hands carry the skin tone in BaseColor and layers 1-2, and multiplying both made them redder than his face.
- Transparency comes from the material's blend type (`.trmtr` alpha type), not `EnableAlphaTest`: `Blend` (glasses lenses: Mable, Corbeau tr0021, Pa Boss ring; Munna), `BlendPreMultiAlpha` (30 Pokémon materials, e.g. Lampent's glass globe), `Add` (glow/energy effects). The shader is usually `IkCharacterTransparent`; opacity is the albedo alpha (Mable's lenses 0.30, verified against the models.spriters-resource rip in `samples/`). Blended materials export as glTF BLEND even when alpha test is also on (it was MASK, which made lenses opaque); `extras.blend` keeps the game mode and `ViewerScene.applyGameBlend` maps Add -> additive, BlendPreMultiAlpha -> premultipliedAlpha.
- Specular is per layer: `SpecularLayerN{Intensity,Offset,Contrast}` lerp over the base values through the `_lym` channels (x `LayerMaskScaleN` x layer enable), like the colours (`importer.bake_layer_specular`). Lebanne's skin is layer 1 = 0.0 while the base 0.74 only covers unpainted texels; reading just the base made her face glossy (game: matte). The per-texel intensity is normalised into `specularMaskTexture` R (`specularIntensity` = its peak); G = per-texel offset as (o+1)/2, B = contrast/2, flagged `extras.shading.specularMaskChannels` (the Game shader then reads them instead of the material-wide intensity-weighted means, which older GLBs still use). A single mean was not enough: the Courier outfit (`ff_drs0002_00` body) has base 0.14/offset 0.4 on unpainted texels but its black trousers (layer 2) are 0.03/offset 0, and a GLB converted before the layer bake gave the whole outfit the 0.14/0.4 highlight (glossy vinyl trousers). Layer specular != base is the norm (185 trainer materials, 2462/3235 ZA Pokémon materials): reconvert any ZA GLB older than this change (SV/LA are PBR and never reach this bake).
- **Material categories:** every `.trmtr` has `ints.CategoryLabel`, exported as glTF `extras.category`. Z-A (all files surveyed): 4 = the character's own body (`face_skin`, `body_skin`, `hairstyle`, `eyebrow`, eyes), 5 = clothing/accessories (`tops`, `bottoms`, `obj_hrs`...), 6 = every Pokémon material, 0 = props. SV numbers them differently (trainer skin 5). The game's rig lights each category with its own `dir_N` / `GILightCommon.ColorN` / `rim_N`. The viewer applies `Environment.categories[cat]` (key/ambient multipliers + a per-category rim light; Lighting tab > Material categories). No preset sets them yet. Asami (`cc_df` Sleeves) VS shot: skin is ~2x brighter relative to her bow than in our render, while the hair is ~4x darker. Skin and hair share category 4, so per-category lights alone cannot explain the dark hair.
- Table-driven NPC hair (`hairstyle` + `ColorTableMap`, one layer) offers its table zones (`own`) followed by the 237 `eyebrow_colors.json` colours (player 32 + NPC tables). The part's table only holds a few authoring swatches; Sleeves' default is cream.
- Not yet read (see `python -m pipeline.audit_materials`): face vertex sub-layers (`EnableVertexSubLayer`, `BaseColorSubLayerN`, vertex colours are dropped), the hue-shift shading terms (`HueShiftBias`, `MidArea*`/`DarkArea*`, `SaturationPower`; exported in `extras.shading.hueShift`, not drawn; nearly constant per category, shifts ±0.1), `BaseColorDarkness`, emission/metallic/specular layers. `tools/skin_check.py` compares face vs body skin per trainer.
- Mesh visibility per clip comes from `.tracm` (`trinity.parse_tracm_visibility`: root[1] shapes, shape[5] -> [2] union of fixed / per-frame bits / keyed bits). Clips carry `visibility` in the manifest; rest visibility = the default clip's frame-0 value, else the majority across clips (Griselle's cup, Bulbasaur's vines, Gengar's long tongue start hidden).
- **Holocast (hologram)**: 57 trainer `.trmmt` files have a `holo` set, and the cc_ NPC parts also have `holo_red` (spellings `horo`, `holo00/01`; `importer.holocast_name` normalises them). Each set points to an alternate `.trmtr` with the same textures plus `EnableHolocastEffect`, `HolocastColor` (linear HDR: cyan 0.223/3.392/3.392, red 6.191/0.442/0.393, tr0019 Pa Boss magenta 3.181/0.843/3.629), `ScanlineSpeed 2`, `ScanlineDepth 0.7`, `ScanlineTiling 260` and `ScanGradationTiling 1`. The scanlines are procedural (no texture), so these sets are not Coloring variants any more: `attach_holocast` writes per-material `extras.holocast[set]` and manifest `holocast` presets (the most common values; composite merges the parts). The viewer's Appearance > Hologram section (`scene/hologram.ts`, `ui/HologramSection.tsx`) redraws the effect on any model: luminance x colour x top light x scanlines. Parts fitted to `samples/hologram_*` rather than read from data: the line pitch (pi/tiling m, about 1.2 cm), the gradient band, opacity and edge glow. The data marks holograms `Opaque`, but every screenshot shows the scene through them, so the viewer blends them with a depth-only prepass (`ViewerScene.applyHoloPrepass`) that draws only the front surface.
- Trainer face meshes carry vertex colours used as shader sub-layer masks (`EnableVertexSubLayer`); never export them as COLOR_0 or the face renders black. The importer drops vertex colours.
- Props: trainer skeletons have `right_attach` / `left_attach` bones (children of the hands); clips scale them 0.01/1 to hide/show a held item. Poké Ball models are `ZA-TrainersNPC.zip ik_chara/model_ob/ob02NN_00_<name>ball/` (0204 = Poké Ball, 0208 = Nest Ball, 27 kinds), ~7.6 cm, pivot at centre, halves skinned to `upper_parts`/`lower_parts`; open/close clips only exist for ob0204 in `ZA-Demo.zip ik_demo/ee/hokaku/`. Which ball a trainer holds is game logic, not data (needs a manual trainer → ball table).
- Remaining shading differences vs the game (ear-base crease, jaw fold on Pikachu) come from vertex normals under PBR lighting; verified identical with the normal map removed. Not a data bug.
- Gas shells (Gastly `smoke`, ZA `IkCharacter` / SV `NonDirectional`, same mesh in both): an OPAQUE sphere (rest radius 0.47) the vertex shader displaces along the normals by `DisplacementHeight` (0.3) x a tileable cloud `DisplacementMap` sampled on UV set `UVIndexLayer3` (1) with `UVScaleOffset3` and panned with shader time (no `.tracm` smoke tracks; the SV `non_directional.bnsh` is stripped Maxwell code, so speed is fitted to footage, ~0.07 UV/s rising). Vertex colour R is the weight, six levels 0.5 (face) .. 1.0 (back); the face shows through a round hole because the face band sinks INSIDE the black body: `importer.gas_displacement` = `H * (w*d - GAS_RETRACT * max(0, 1 - w/GAS_RETRACT_END))`, `w = (R-0.5)*2` (1.0 / 0.45: the face band w <= 0.2 sinks >= 0.17 m, the ring band w = 0.4 only 0.03 m). Measured on the rest pose: the shell is 0.04-0.18 m outside the body over the face and 0.06-0.19 m at the ring/back, so a uniform sink buries the face or exposes the sides, and linear/quadratic weight pulls sank the ring too (hood of gas over an exposed lower body). Translucent density-alpha was wrong (in-game lumps are solid, hard-edged). The exact shader formula and panner speed are fitted to footage, not read from data. The GLB bakes frame 0 and carries `extras.gas` + `gasDensityTexture` + `_GASWEIGHT` for the viewer's panner (`viewer/src/scene/gas.ts`, displaces by `H*w*(d(t)-d(0))`). Predicate `_is_gas_shell`: DisplacementMap + height >= 0.25, not `Unlit`, no alpha test (excludes Blaziken flames, Blastoise jets; Koffing/Weezing `SSSEffect` 0.25 with 0..0.8 colours keep a plain push, unverified). Partition masks (R+G+B+A = 1) need the cumulative-sum normalisation for BOTH the lit and the shadow bake, or the white albedo survives the sequential lerp (grey Gastly). `NonDirectional` = lit without N.L (`shading.nonDirectional`, Game shader uWrap 1), not emissive. The body is always painted OVER the gas in game (a perfect disc in every shot, never a gas 'wig' across the face): the viewer draws gas meshes at `renderOrder -10` with `depthWrite=false` (`ViewerScene.applyShading`), so `GAS_RETRACT` is now 0 (no sinking needed: the shell is a plain `H*w*d` push and the body covers the face band; sinking only thinned the ring at the sides/bottom). Weights are smoothed over mesh neighbours (`GAS_WEIGHT_SMOOTH`) and the shadow tint is a dark indigo (0.2, 0.2, 0.28) instead of the magenta `ShadowingColorLayerN`.

## Modular generic NPCs (`cc_<base>`, ZA)

`ZA-TrainersNPCCommon.zip`: `model_cc_base/<b>/<b>_base.trskl` is a skeleton only (bu kid, dm adult M, em stocky M, fm fit M, gm tall M, rv rival); `model_cc_vr/{face,hrs,drs}/<b>_<kind>NNNN_VV_<name>/` are the swappable parts (face / hair / outfit; VV = colourway). `ZaCatalog.cc_models()` yields one model per base (`cc_dm` ...), built by `importers/za/composite.py` with every part as separate meshes tagged `extras {group, option}`; the manifest gets `partGroups` and the viewer's "Appearance" section shows one option per group (default = `NNNN_00` of each).

- Vertex joint indices address a combined palette: base rig at 0..73, each part's own bones at that part's `trskl.palette_offset` (face 164.., outfit 204..). Parts list their bones as root nodes whose local transform is relative to a base bone (face -> `head`, skirt -> `waist`, found numerically from the bind pose). The composite gives each part its own palette positions and remaps primitive joints, so different dresses with same-offset skirt bones do not collide.
- Clips: `motion_cc_base/<b>/<set>/` (first set bare names, others ` [tag]`, `Clip.group`). Per-part cloth/face expression anims (`motion_cc_vr`) are not imported. `df`/`ff`/`gf` (female) parts and clips exist but their base skeletons are not in the rip, so no female composite.
- Female prefixes `df`/`gf`/`ff` have parts and clips but no base skeleton in the rip; they bind to the same rig as `dm`/`gm`/`fm` (`CC_SKELETON_DONORS`; verified: identical joint indices 0..73, clip first-frame translations equal to 3 dp, shipped `tr0031_00_co_member_f` bind positions identical to `dm_base`). `ff` has no `motion_cc_base/ff`, so it uses the `fm` clips. Models `cc_df/cc_gf/cc_ff`.
- Colour comes from `ColorTableMap` (`*_90_alb`, `ColorTableDivideNumber` = 1..32 zones, top row lit / bottom shadow) with `_lym` channels as layers 1..4 and `BaseColorIndexN` picking zones; `LayerMaskScaleN` = 0 disables a layer (mask alpha is often fully on). Modular materials (`import_model(skin_tones=True)`) bake masked-only (untinted where no channel covers; skin keeps layer 1 as base). Nearly everything is palette-driven: outfit tops/bottoms/body/accessories, hair, eyes, eyebrows, eyewear, skin. The per-NPC indices are runtime game data (no table in the rip), the trmtr values are authored per-part defaults (not always 1..4).
- Skin tone textures are keyed by albedo + mask + colour-table hash (`skin_key`): outfits share `sh_body_skin_01_alb` but paint other mask layers (Artist F `df_drs0010_00` hands = layers 2/3, zones 9/10 orange/blue); keyed by the albedo alone the first-registered plain skin texture won and the paint vanished. Reconvert `cc_*` GLBs older than this.
- Skin: `body_skin`/`face_skin` share zones 1..4 (deep..pale), exposed as a `skin` variant group (Tone 1..4, default 3) so head and body match; the body's authored `BaseColor` tint is dropped. Other palettes: material `extras.palette` (raw albedo + mask textures, zone colours, default indices) lets the viewer recolour at runtime (`viewer/src/scene/palette.ts`, Appearance section swatch rows per layer); manifest `partGroups[].options[].palettes` describes them. Eyes use masked-only + layer scales (iris only; the old whole-texture tint made them black). The layer mask ships as two opaque images (`palette.mask` RGB, `palette.maskA` alpha as grey): canvas reads premultiply alpha and zero RGB where A=0, which made every recolour fall back to the near-white raw albedo ("model goes white").
- Wrinkle strokes: some skin masks paint thin strokes (brow furrow, smile/nose lines; Adult A F's toenails) as a layer 2-4 in the skin's OWN zone (Rust Grunt M/F `tr0030/tr0031` layer 3 zone 3 = skin, Jub F 4/4, Ga M B 4/4). Under the lerp-replace colour-table blend they are invisible at the authored tone, yet the game shows the Grunt's furrow darker than his skin (`samples/za_rust_syndicate_grunt_vs.png`). Kept at the authored zone they became pale lines at deeper tones; following the tone hid them. Rule (`skin_zone_layers` + `deeper_skin`, user decision 2026-10-23): they follow the selected tone one shade deeper (tone t -> zone t-1; tone 1 -> zone 1 x zone 1/zone 2), no coverage floor (Grunt F's cover 0.03%); the viewer's runtime re-bake does the same (`palette.ts deeperSkin`, `skinLayers`). Tried and rejected: a multiply-stacking blend (`tint = prod lerp(1, zone, mask)`) also darkens same-zone strokes, but it changes ~720 of 1473 colour-table materials, e.g. the player hair mask has R and B fully on in zone 2, which would square the hair colour.
- Colour-table shadow row is not always a shadow: ~11% of cells (mostly under near-black brow/eye/hair zones) hold a brighter, vivid colour (Schoolkids F `bu_face0003_00`: green (80,138,90) under #252626 brows, which rendered green brows). `importer.table_shadow_cell` replaces any shadow cell brighter than 0.95x its lit cell with 0.78x the lit colour (keeping its hue at lower luminance left the brows dark green; black stays black), in both `apply_color_table` and `extras.palette.shadow`. Colour-table bakes are keyed by table + `BaseColorIndexN` + scales (`ct_sig`): faces share albedo + mask files, and keyed by the albedo name every Child face showed face 0000's brows. The viewer's swatch popover shows each distinct colour once (tables repeat colours across schemes and pad unused cells with black).

- **Alternate versions borrow clips:** the DLC re-models without motion data whose folder is the original's plus one letter (`tr1100_sfire` <- `tr0280_fire`, Team Star `sbattle/spoison/smr/seviil`, `tr1900_primitiveo` <- `tr0000_primitive`, `tr1920_futureo` <- `tr0020_future`) play the original's `motion_uq` clips (`SvCatalog._variant_donors` / `_borrowed_animations`): shared bones must have the same parents and the borrower must have >= half the donor's joints; shared bones whose bind offset differs > 2 mm keep rotations only (`AnimationFile.rotation_only`: Fire `foot_base` 22 mm, Fairy arms 27 mm); the new outfit bones stay at rest. - **Body types (`.trbsm`, imported):** every base-game generic is authored on the same Adult M skeleton AND an Adult-M-sized mesh (the Youngster's bind pose was 1.76 m); the game reshapes them at runtime. `.ccdata` root[1] = {0 `bsm/chara_create_value_list_<t>.trbsm`, 1 per-NPC mesh-scaler weights (x, y, z), 2 slider weights}; all weights are 1.0. Tables used: dm (Adult M, identity), df (women), f (fit men), ef, em (stocky: the Cleaner `tr0470`, English "Janitor"; DLC `tr1390` "Janitor" is someone else), a (Youngster). `.trbsm`: [0] 12 sliders {name, bones, max, flags (`head` 0x2001)}, [1] 21 `mesh_scaler_<bone>` {bones, flags (low byte = axis mask), per-axis max}, [2] {foot: foot_base}. `importers/za/trbsm.py apply_body_type` (after `split_scale_joints`): a slider scales its bones' meshes uniformly and their children's offsets (segment-scale-compensate), the flagged head slider is inherited by the head subtree, a mesh scaler adds per-axis girth to the bone's skin leaf only, then `_reground` shifts `foot_base` so the soles stay on y = 0. Results: Youngster 0.99 m, Cleaner stocky, PC lady (`tr0510`, df) slimmer so her apron's Poké Ball is round (it was 26% too wide; the Kitakami nurse `tr1370` is a DLC `model_uq` authored at final size and has no table). The lerp `1 + (max - 1) * w`, the head flag and the re-grounding are hypotheses (`docs/ledger/sv.json`). DLC generics have no `.ccdata` and keep the Adult M build.

## Pokémon Stadium 2 (`--game stadium2`)

N64, read straight from the user's ROM (`~/Documents/pokemon_raw_data/roms/Pokemon Stadium 2 (USA).z64`, env `POKEMODELS_STADIUM2_ROM`, `--data`; any of .z64/.v64/.n64). Offsets verified on US 1.0 = the build pret/pokestadiumgs decompiles (MD5 `1561c75d11cedf356a8ddb1a4a5f9d5d`; the decomp maps code only, assets are one unlabelled `bin`). Code: `pipeline/importers/stadium2/{rom,fragment,importer}.py`, `pipeline/catalog/stadium2.py`; own code written from the format (Stadium 1 notes in the Dramatic Shape mod's `model_extract/README.md` and pret/pokestadium `src/12D80.c`; neither has a licence, nothing vendored). Unread values: `docs/ledger/stadium2.json`.

```bash
PYTHONIOENCODING=utf-8 ./.venv/Scripts/python.exe -m pipeline --game stadium2 list          # 282 models
./.venv/Scripts/python.exe -m pipeline --game stadium2 convert --id pm0025 --id ex0254         # ~0.2 s each, no Blender
```

- **Model archive `0x27ED000`** (`u32 tag, 0, total, count` + `{offset, size, 0, 0}` records): 282 `PERS-SZP`-wrapped Yay0 `FRAGMENT` modules linked at 0x8FF00000. Root struct (found from the entry stub's `lui/addiu`): u16 species = entry index, +8 geo layouts, +0xC skeletal clips (EMPTY in Stadium 2), +0x10 texture clips (eye/mouth swaps). Ids: 1..251 `pm####`; `ex0254..ex0278` Unown B..Z (A = `pm0201`), `ex0253` Egg, `ex0279` 2nd Pikachu, `ex0280` Poké Ball, `ex0281` 2nd Ho-Oh, `ex0000` stage set, `ex0252` unidentified (labels by rendering, display only).
- **Clip bank `0x2D7D000`**: 282 uncompressed entries in the same order, each an archive of clips; a clip entry = u32 header offset + data, pointers relative to the entry. Header = Stadium 1's {u16 flags, u16, start, loop start, channels, frames, chanTable, scale, rotation, translation}; 3 channels per bone (bone `chan` field), 10-byte channel records {nScale, nRot, nTrans, interp, oScale, oRot, oTrans}. flags 1 loop (always clip 0 = `idle`), 2 one-shot, 4 16-bit translations, 8 hermite keys. Packed mode: one bit-packed value per frame (12-bit signed rotations x16 = binary angle; scales s16/1000). Hermite mode (Pidgeot, Dodrio, Exeggutor, Magmar): keys of s16 (frame, value, out-slope[, in-slope]), offsets in s16 units, rotations in 0.1 deg, scales /100, count < 2 = the offset field is the value. 30 fps. **Clip names** come from the per-species action tables (ROM 0x1718000, `tools/gen_stadium2_clip_roles.py` -> `pipeline/catalog/stadium2_clip_roles.json`): every species has a record for EVERY move (Metronome can call any), so a clip's move list is an animation class, not the species' moveset. `catalog/stadium2.role_label`: action 255 `damage`, 254 `faint` (user-identified: usually the last and second-to-last clip), 264 `faint (airborne)` on birds; else all moves when <= 3 (Pikachu `anim_09 Surf, Rapid Spin`), else only moves the species learns by TM/HM (base-stat table 0x98F21, the ROM's only movepool; no level-up learnsets found), else bare `anim_NN`. Full lists in manifest `extras.clipMoves`.
- **Geo layout** (`GEO_SIZES`, + Stadium 2's 4-byte 0x28/0x29): node stack decides parents and the drawing bone; 0x1D bone {id, flags, chan, T s16, R s16 binary angles, S 16.16}, 0x1C root scale (0.1), 0x17 texture/palette tables, 0x23 material {+1 combiner mode, +2 texture-clip channel, +4 DL, +8 texture, +0xA palette, +0xC RGBA colour; mode 1 forces white}, 0x22/0x1E/0x20/0x21 display lists, 0x08 effect callbacks (fire/gas drawn by battle code: recorded in manifest `extras.effects`, not drawn). F3DEX2 lists: vertices bone-local and rigidly bound; the vertex cache persists across lists (the game's joint blend). Texture sampling emulates the render tile (`importer.tile_axis`): `G_SETTILE` shift, minus the `G_SETTILESIZE` origin, clamp to the tile size, then wrap by 2^mask with mirroring; clamped axes are baked over the whole tile (often wider than the texture: cms 3 = mirror + clamp, Arbok's hood face, Charizard's wings).
- **Skeleton rule** (game keeps scale out of the matrix chain): pivot joint `boneNN` (T x parent's accumulated scale, R) + leaf `boneNN_scale` (accumulated scale, carries the skin); children hang under the pivot. Bones scaled to 0 at rest (parts clips reveal: Pikachu's surfboard) bind with 1 in place of 0. `model_root` = root scale x `UNIT` 0.015 (FITTED: Pikachu ~0.4 m).
- **Materials = the game's combiner presets** (`importers/stadium2/combiner.py`): the 0x23 mode indexes a 15-row two-cycle table read from ROM `0x956AC` (identical to Stadium 1's `D_8006F1B4`), evaluated on the CPU and baked into the texture only where it changes the texel. Rows 5-9 have no SHADE: unlit, written as black base + emissive (UNITE's convention; Ponyta/Rapidash/Moltres flames). A part with texture -1 is drawn with texturing off, so TEXEL0 reads black (Unown is black: user-confirmed), UNLESS (a) its texture-clip channel supplies the texture (rest = first clip's frame 0: Chinchou's glowing orbs) or (b) it follows a geo 0x08 node with callback `0x81000140` = the layered env material (`fragment.env_material`, decoded from fragment 26's func_810024E0: arg -> M {+0 base {texture address}, +0xC texgen layers (gSPTexture 0x1194)}). Base = layer image -> N64 texture generation = sphere map: `extras.sphereMap`, viewer `scene/sphereMap.ts` samples the map by the view-space normal, GLB UVs hold the front-view lookup (55 materials: Unown, Umbreon, Murkrow, Steelix, Scizor, Skarmory, Lugia, Magcargo, Lanturn...). Base != layer (Porygon2's pink body, Umbreon's yellow rings, Skarmory): base by mesh UVs, the reflection layer is not drawn (`extras.stadium.envLayer`, ledger `material:envLayer`).
- Blender's glTF importer mis-poses these scaled binds (inspect renders are blank, bounds ±200 m): render with `tools/render_models.mjs` (dev server), as for UNITE.
- Gaps: texture clips are in the GLB/manifest (`extras.flipbook`, `extras.textureClips`) but the viewer does not play them; the env reflection layer over a different base (7 materials); geo 0x28/0x29 (Magcargo) unread; effects; clip names. Bone ids can repeat (Charmander: two unanimated id-25 bones): repeated ids are named `boneNN_<index>`.
